# Query Patterns

Use these patterns to keep research focused.

## Startup/Product Validation

Search lanes:

```text
"<problem phrase>" software
"<problem phrase>" startup
"<job-to-be-done>" tool
"<buyer role>" "<pain phrase>"
"<category>" pricing
"<category>" reviews
"<category>" alternatives
site:g2.com "<category>"
site:producthunt.com "<problem or category>"
site:reddit.com "<problem phrase>" "<buyer role>"
site:apps.apple.com "<category or product phrase>"
site:play.google.com "<category or product phrase>"
```

Look for:

- Direct competitors
- Adjacent products
- Manual service providers
- Internal tools or spreadsheets
- Forums where users describe pain
- Pricing and packaging
- Reviews that reveal gaps
- Recent launches or shutdowns

## Competitor Scan

```text
"<company/product>" pricing
"<company/product>" alternatives
"<company/product>" reviews
"<company/product>" customers
"<company/product>" case study
"<company/product>" docs
"<company/product>" API
```

Check:

- Official website
- Pricing page
- Product docs
- Customer logos or case studies
- Changelog/blog
- App store or extension listing
- Funding/news only if relevant to traction or timing

## Technical Comparison

```text
"<technology A>" "<technology B>" benchmark
"<technology>" docs
"<technology>" limitations
"<technology>" GitHub
"<technology>" API reference
"<technology>" changelog
site:github.com "<technology>" "<use case>"
```

Prioritize official docs, repos, standards, benchmark methodology, and recent version notes.

## Regulation or Standards

Use primary sources:

```text
site:.gov "<topic>" regulation
site:ec.europa.eu "<topic>"
site:iso.org "<standard>"
site:nist.gov "<topic>"
```

Do not rely on summaries alone when the answer affects compliance or risk.
